# CAP 개발 계획

CAP은 개인 프로젝트다. 전부 Rust로 쓰고, 작은 로컬 모델에서 먼저 잘 돌게 만든 다음 큰 모델과 다른 서버로 넓힌다.
철학은 [PHILOSOPHY.md](PHILOSOPHY.md)에 있다.

## 목표

1. **작은 로컬 모델 우선.** 9B급 모델, 8천~1만 6천 토큰 문맥에서 끝까지 일을 마친다.
2. **최적화된 에이전트.** 실행 파일 하나, 빠른 시작, 모델이 쓰는 글자와 호출 횟수를 줄이는 구조.
3. **Codex, Hermes의 하네스보다 나은 결과.** 같은 모델을 붙였을 때 더 많이 풀고, 거짓 "됐다"가 적고, 더 빨리 끝난다.

## "더 낫다"의 기준

6단계에서 같은 모델, 같은 과제, 같은 채점으로 세 에이전트를 돌려서 아래 네 숫자를 비교한다.

| 항목 | 뜻 |
|---|---|
| 푼 과제 수 | 숨겨 둔 채점 테스트를 통과한 과제 |
| 거짓 "됐다" 수 | 끝났다고 했지만 채점에서 떨어진 과제 |
| 걸린 시간 | 과제 하나를 마칠 때까지의 벽시계 시간 |
| 쓴 토큰 | 입력과 출력 토큰 합 |

이 비교를 마친 뒤에 결과를 그대로 적는다. 현재 비교 측정은 0건이다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | Python 판을 `archive/python`으로 옮기고 Rust 작업 공간을 만든다 | 완료 |
| 2 | 핵심 루프, 기본 도구, 테스트 판정, 권한 표, 모델 서버 연결, `cap exec` | 완료 |
| 3 | 줄 번호 편집, 운영체제 격리(Windows AppContainer, Linux Landlock), 스트리밍, Ctrl-C 처리 | 완료 |
| 4 | 작업 상태판, 코드 지도, 캐시에 맞춘 프롬프트 배치, 테스트 미리 돌리기 | 완료 |
| 5 | 대화 화면(`cap`), 스킬과 MCP 호환, 사용자 설정 파일, 모델 크기별 도구 묶음 | 완료 |
| 6 | Codex, Hermes와 같은 모델·같은 과제 비교 | 예정 |

## 구현된 것

### 2단계: 뼈대

- **루프** (`agent.rs`): 모델 호출 → 도구 실행 → 완료 주장 시 테스트 판정. 상태는 `verified`, `unverified`, `answered`, `tests_fail`, `step_limit`, `stuck`, `model_failed`, `context_full`, `interrupted`.
- **도구** (`tools.rs`): `read_file`, `list_files`, `search`, `replace_lines`, `edit_file`, `write_file`, `run_tests`, `run`, `note`, `use_skill`, 그리고 MCP 서버의 도구.
- **테스트 판정** (`gate.rs`): Cargo, pytest, npm, Go 프로젝트의 테스트 명령을 파일에서 알아내고 결과를 통과, 실패, 테스트 없음으로 가른다.
- **권한 표** (`perm.rs`): `read`, `edit`, `auto` 세 모드. 읽기 전용 명령과 테스트 실행은 바로 돌리고, 그 밖의 명령은 `edit` 모드에서 먼저 묻는다.
- **문맥 관리** (`context.rs`): 토큰을 어림하고, 서버가 알려 준 실제 값으로 어림을 보정하고, 창이 차면 오래된 도구 출력부터 줄인다.
- **모델 연결** (`openai.rs`): OpenAI 호환 형식. Ollama, LM Studio, KAU, OpenAI, Anthropic, Gemini, OpenRouter를 이름으로 고른다. 기본은 Ollama.

### 3단계: 편집, 격리, 화면에 바로 보이기

- **줄 번호 편집** (`edit.rs`, `view.rs`): `replace_lines`는 줄 범위와 새 내용만 받는다. 모델이 지금 상태로 본 줄에만 적용하고, 아직 보지 않은 줄이면 그 줄을 보여 준 다음 같은 호출을 다시 받는다. 새 내용에 들여쓰기가 빠져 있으면 바꾸는 줄의 들여쓰기를 붙인다.
- **찾아 바꾸기 편집** (`edit.rs`): `edit_file`. 들여쓰기나 줄 끝이 조금 달라도 맞는 자리를 찾고, 실패하면 가장 비슷한 줄을 알려 준다.
- **운영체제 격리** (`sandbox/`): Linux는 Landlock으로 명령이 프로젝트, 임시 폴더, 빌드 캐시에만 쓰게 한다. Windows는 AppContainer로 `cap sandbox setup`에서 넘겨준 폴더만 열게 하고 네트워크를 막는다. `--sandbox auto`는 격리가 되는 곳에서는 격리하고, 안 되는 곳에서는 그 사실을 첫 줄에 알린다.
- **스트리밍** (`openai.rs`, `term.rs`): 모델의 글이 오는 대로 화면에 나온다. `--no-stream`은 답이 다 온 뒤에 보여 준다.
- **Ctrl-C** (`cancel.rs`): 돌고 있는 턴과 그 턴이 띄운 명령을 멈추고 `interrupted`로 끝낸다. `cap exec`의 종료 코드는 130이다.
- **도구 호출 강제** (`--strict-tools`): 서버에 `tool_choice: "required"`를 보내 모든 답을 도구 호출로 받고, 끝은 `done` 도구로 알린다. 이 옵션을 거절하는 서버에는 옵션을 빼고 다시 보낸다.

### 4단계: 모델이 길을 잃지 않게

- **작업 상태판** (`board.rs`): 매 요청의 끝에 몇 번째 단계인지, 바꾼 파일과 읽은 파일, 테스트 상태, 다음에 할 일을 400자 안으로 붙인다.
- **캐시에 맞춘 배치** (`agent.rs`): 지시문, 파일 목록, 스킬처럼 바뀌지 않는 것을 앞에 두고 과제를 뒤에 둔다. 상태판은 보내는 사본에만 붙이므로 저장된 대화의 앞부분은 호출마다 같다.
- **코드 지도** (`codemap.rs`): 첫 프롬프트의 파일 목록 옆에 파일마다 들어 있는 함수와 타입 이름을 적는다. Python, Rust, JavaScript·TypeScript, Go, Java, Kotlin, C#, C·C++을 읽는다.
- **하네스가 먼저 움직인다** (`agent.rs`): 과제에 이름이 나온 파일은 첫 프롬프트에 미리 넣는다. 파일을 바꾼 뒤에는 테스트를 스스로 시작해서, 빨리 끝나면 도구 결과에 함께 싣고 오래 걸리면 모델이 다음 글을 쓰는 동안 계속 돌린다.

### 5단계: 쓰는 사람을 위한 것

- **대화 화면** (`chat.rs`): `cap`만 치면 대화가 시작된다. `/help`, `/status`, `/mode`, `/model`, `/clear`, `/skills`, `/mcp`, `/quit`.
- **모델 크기별 도구 묶음** (`tools.rs`): 문맥 1만 6천 토큰까지는 도구 6개와 짧은 설명(`small`), 6만 4천까지는 `list_files`와 `edit_file`을 더하고(`standard`), 그보다 크면 `note`까지 준다(`full`).
- **스킬** (`skills.rs`): `.cap/skills`, `.claude/skills`, `.agents/skills`의 `SKILL.md` 폴더를 읽는다. 프롬프트에는 이름과 설명 한 줄만 넣고 본문은 `use_skill`로 꺼낸다.
- **MCP** (`mcp.rs`): 설정 파일에 적은 서버를 띄워 그 도구를 `mcp__서버__도구` 이름으로 모델에 준다.
- **설정 파일** (`config.rs`): `%APPDATA%\cap\config.toml` 또는 `~/.config/cap/config.toml`. 명령줄 옵션이 환경 변수를 이기고, 환경 변수가 설정 파일을 이긴다. `cap config`가 지금 적용된 값을 보여 준다.

## 확인한 것

- 단위·통합 테스트: Windows 153개, Linux 152개. 격리 테스트는 실제 명령을 격리 안에서 돌려 확인한다.
- 실제 모델로 돌려 본 것: KAU 서버의 `qwen3.5-9b`로 한 줄 버그 고치기(두 번 모두 모델 호출 4번, 17.9초와 25.1초)와 대화 화면에서 질문 하나. 한 번씩 돌려 본 것이고 측정은 아니다.
- 기능 하나하나가 실제 모델의 성공률과 시간에 주는 효과는 6단계에서 잰다.

## 버전

- Rust 판은 `0.15.0-alpha.1`에서 시작한다. 알파 동안은 `main`에서 개발한다.
- Python 판의 마지막 버전은 태그 `v0.14.0`이고, 소스는 `archive/python`에 있다.
